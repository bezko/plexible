Plexible

Local by design. v1 · caddy + socat Make Plex stop calling your reverse-proxied clients “remote”.
No Plex Pass plx-001 · stereo

Plex decides “local” from the source IP. Put a proxy in front of it and the source becomes the proxy — so playback gets classified remote and Plex asks for a Pass.

Plexible inserts a tiny TCP hop that dials Plex from a LAN address, strips the headers Plex trusts over the socket, and fixes the redirect back. Nothing to patch, nothing to license.

The signal chain

  ┌───────────────────────┐     ┌───────────────────────┐     ┌───────────────────────┐     ┌───────────────────────┐
│         Client        │────>│         Caddy         │────>│      Local Proxy      │────>│          Plex         │
│                       │     │    (Reverse Proxy)    │     │      (Container)      │     │     (Media Server)    │
└───────────────────────┘     └───────────────────────┘     └───────────────────────┘     └───────────────────────┘
            │                             │                             │                             │
 HTTPS request                      Strip headers              Connect from LAN IP             Sees LAN source
                                   Rewrite headers                                           Classifies as local

Caddy terminates TLS and deletes every header Plex would use to guess the real client (X-Forwarded-For, X-Real-IP, X-Plex-Forwarded-For, Forwarded, Referer, Origin). The proxy container then opens a new socket to Plex using a LAN source address, so the only thing Plex can classify on is that local source.

Three moves

01 · Strip

Plex prefers forwarded headers over the socket address. Delete them and the socket wins.

02 · Hop

A socat container listens on a spare port and dials Plex from the host’s LAN IP, not from loopback or a bridge.

03 · Rewrite

Plex’s redirect still points at the internal URL. Caddy rewrites Location back to the public name.

Quick start

  1. Clone the repo and copy .env.example to .env.
  2. Set LAN_IP to the host address Plex already trusts, and put your proxy hostname in ADVERTISE_IP.
  3. Point Caddy at the local proxy port and keep the strip/rewrite headers.
  4. Configure Plex: allowed networks must cover your LAN, custom connections must include the proxy URL.
  5. Verify in the Plex log: requests should read (Subnet), never (WAN).
# docker-compose.yml (excerpt)
services:
  local-proxy:
    image: docker.io/alpine/socat:latest
    network_mode: host
    command: TCP-LISTEN:32402,fork,reuseaddr TCP:${LAN_IP}:32400
    restart: unless-stopped

  caddy:
    image: docker.io/library/caddy:latest
    network_mode: host
    volumes: [ "./Caddyfile:/etc/caddy/Caddyfile:z" ]

Caddyfile

https://plex.example.net {
    tls internal
    reverse_proxy 127.0.0.1:32402 {
        # headers Plex trusts more than the socket
        header_up -X-Forwarded-For
        header_up -X-Forwarded-Host
        header_up -X-Forwarded-Proto
        header_up -X-Real-IP
        header_up -X-Plex-Forwarded-For
        header_up -Forwarded
        header_up -Referer
        header_up -Origin

        # send the browser back to the public name
        header_down Location https://plex.example.net/web/index.html
    }
}
Why this is robust: it does not depend on which VPN, tunnel or overlay you put in front. If the last hop to Plex is a LAN socket and no forwarding headers survive, Plex classifies it local — tailscale, wireguard, cloudflared, whatever.

Reading Plex’s log

# local — good
DEBUG - Request: [192.168.1.10:52334 (Allowed Network (Subnet))] GET /identity
# remote — the thing we are fixing
DEBUG - Request: [100.64.0.7:52334 (WAN)] GET /identity

If the source is 127.0.0.1 you will see (Loopback), which Plex also treats as local — but a real LAN address is more predictable across versions.

Caveats, honestly

This is a workaround, not a promise. Plex changes its classification logic between releases, and 2026 builds enforce remote access server-side. Plexible fixes the local/remote signal; it cannot override an account-level entitlement. Test after every Plex upgrade. Use it on networks you own, and respect Plex’s terms.
